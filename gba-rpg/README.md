# Butano RPG Framework (GBA)

[Butano](https://github.com/GValiente/butano) で作る、クラシックなドラクエ風ターンベースRPGの基礎フレームワークです。
完成品ではなく「ここから町・ダンジョン・敵・魔法を足していける土台」を目指しています。

## デモでできること

- タイトル画面（はじめから / セーブがあれば つづきから / Language で日本語⇔英語）
- 村を歩く（十字キー、タイル単位の移動、壁・NPCとの衝突判定、カメラ追従）
- NPC・看板と会話（A）、宿屋で全回復（10G）、宝箱（一度開けたら空。開封状態はセーブされる）、道具屋（購入・売却）、回復の泉（生存者のHP/MPを全回復。戦闘不能は蘇生できない）、最初のダンジョン「洞窟」（フィールド南東の岩山の門から入る。3フロア、階段で移動、宝箱3つ、フロアごとに強くなる敵、スケルトンは3Fのみ）、歩き回るNPC（村人と長老。ランダムに歩き、話しかけも可能）、装備（STARTメニュー > Equip。武器・防具で攻撃/防御などが変わり、戦闘にも反映。職業ごとに装備できる物が違う）
- 南の門から外のフィールドへ（マップ間ワープ）
- フィールドでランダムエンカウント → ターンベース戦闘（たたかう / わざ / どうぐ / にげる）
- 素早さベースの行動順、攻撃・技（MP消費）・アイテム、経験値とレベルアップ（最大Lv100）、レベルによる技習得
- 敵のランク（通常 / ボス / ラスボス）に応じた複数回行動
- マップ名の一時表示（シーン開始時・ワープ時に画面上部中央へ約1.75秒）と、右上の常時ミニマップ（`v ^ < >`=自分と向き / `#`=壁 / `.`=床 / `~`=水・溶岩 / `O`=出入口 / `!`=話す・調べる対象 / 空白=マップ外）
- フィールドメニュー（START）：ステータス / 道具 / 技（回復系のみ） / 装備 / セーブ（SRAM） / サウンド
- 仮の BGM（タイトル・町・ダンジョン・通常戦闘・ボス戦・重要イベント2曲）と SE（決定・キャンセル・攻撃・ダメージ・レベルアップ・宝箱）、音量調整とミュート

| ボタン | フィールド | メニュー・戦闘 |
| --- | --- | --- |
| 十字キー | 移動 | カーソル |
| A | 話す・調べる | 決定 / メッセージ送り |
| B | – | キャンセル / 前のキャラに戻る |
| START | メニューを開く | – |

> 既定の言語は日本語です。第1章〜第10章の会話・看板・宿屋/泉/宝箱のメッセージ・マップ名・タイトルが日本語になります。
> タイトル画面の `Language` で英語と切り替えられます（「日本語対応」の項を参照）。
> 戦闘メッセージ・コマンド、フィールドメニュー、装備メニュー、道具屋、アイテム名・呪文名・敵名・仲間の名前も日本語になります（`HP` / `MP` / `Lv` / `G` などの略号は共通）。

## セットアップ（devkitPro + Butano）

1. **devkitARM** を入れる: <https://devkitpro.org/wiki/Getting_Started> （`gba-dev` グループ）。
   `DEVKITPRO` / `DEVKITARM` 環境変数が設定されていること。
2. **Python 3** を入れる（Butano のアセット変換で使用）。
3. **Butano** を取得する:
   ```sh
   git clone https://github.com/GValiente/butano.git
   ```
4. ビルドする。`LIBBUTANO` には Butano リポジトリ内の `butano/butano` フォルダを指定します:
   ```sh
   cd gba-rpg
   make -j8 LIBBUTANO=/path/to/butano/butano
   ```
   このリポジトリと `butano` を同じ親フォルダに並べて置いた場合は、既定値（`../../butano/butano`）のまま `make -j8` だけで通ります。
   Windows などで `python3` コマンドが無い場合は `make PYTHON=python` を付けてください。
5. できあがった `butano_rpg.gba` を mGBA などのエミュレータ、または実機で起動します。

Butano 公式の導入ガイド: <https://gvaliente.github.io/butano/getting_started.html>

## 設計のポイント

### データ駆動
ゲーム内容は `src/data/*.cpp` の `constexpr` 配列だけで定義します。ROM に置かれるので RAM を消費しません。

- **魔法とアイテムは同じ `Effect` 構造体**（種類・対象・威力・ばらつき）を共有し、戦闘でもフィールドでも同じ処理で解決されます。
- **キャラのステータスは保存しません。** 常に「職業 + レベル」から計算するので、バランス調整はテーブルを書き換えるだけで、セーブデータも小さくなります。
- **マップは ASCII アート**で書きます（1文字 = 16x16 タイル）。行の長さ違い・未定義の文字は `static_assert` でビルドエラーになります。

### シーン
`FieldScene` / `BattleScene` はスタック上に1つずつ生成され、抜けると背景・スプライト（VRAM）が解放されます。
シーンをまたいで残す情報はすべて `GameState` に置きます。

### UI
- ウィンドウ枠は動的な背景レイヤー（`bn::regular_bg_map_item`）に描き、文字は `bn::sprite_text_generator` のスプライトです。
- `Window` / `Menu` / `MessageBox` は RAII で、スコープを抜けると枠と文字が消えます。
- `Menu::run()` などはブロッキング（内部で毎フレーム `Ui::update()` を呼ぶ）なので、会話や戦闘の流れを上から下へ素直に書けます。
- 固定幅フォント（`Ui::fixed_text_generator()` / `Window::print_fixed()`）は、桁を揃えたい表示（ミニマップ）用です。
- データ表（敵・アイテムなど）は行の順番が enum の並びと一致している必要があります。新しい行は enum の最後に足した位置と同じ場所（表の最後）に書いてください。
- 装備品は `ItemData` の一種で、キャラごとの装備枠は `PartyMember::weapon/armor`。`PartyMember::stats()` が「職業+レベル+装備補正」を返し、戦闘も各メニューもこれを使います。
- 歩くNPCの実行時の状態（`Walker`、最大4体）は `FieldScene` が固定容量で持ちます。プレイヤーと同じく「移動先を先に予約」し、1歩の間は元のマスも塞ぐので重なりません。AIは待ち時間が尽きたときだけ働くので、毎フレームの負荷はほぼカウントダウンだけです。
- 「通れるか」の判定は `MapData::walkable()` の1か所だけ（移動・ミニマップ・セーブ読み込み時の位置チェックで共通）。
- ロード時は `GameState::position_safe()` で位置を確認します（通れるタイルで、隣に1マス以上進める場所があること）。だめなら現在の章の復帰地点へ戻し、復帰地点がふさがっていればその周囲の空きタイル、最後の手段としてニューゲームの開始地点を使います。壊れた向きの値は下向きに直します。
- セーブデータの大きさは固定です（所持品は `max_items` = 32種分の枠、フラグは64個）。アイテムやフラグを足しても形式は変わりません。形式を変えるとビルド時の `static_assert`（`sizeof(SaveData)`）が止まるので、`save_version` を上げて数値を更新してください。
- ロード時、HP/MPが現在の最大値を超えていたら（装備の補正を調整した後など）セーブを捨てずに最大値へ丸めます。
- ロード時、保存位置がもう通れない場所なら（マップを書き換えた後など）開始位置に戻します。
- フィールド右上のマップ名とミニマップは `FieldScene` が `bn::optional<Window>` で持ち、STARTメニューを開く間だけ閉じます（ウィンドウを重ねないため）。
- 表示の重なり順: マップ背景(3) < プレイヤー・NPC・敵(2) < ウィンドウ(0) < 文字。

### GBA のメモリ制約への配慮
- ヒープ（`new`）は使いません。可変長データは `bn::vector<T, N>` / `bn::string<N>` の固定容量です。
- 背景セルの大きなバッファ（マップ 64x64 セル = 8KB、UI 32x32 セル = 2KB）は `BN_DATA_EWRAM_BSS` で EWRAM に置き、32KB しかない IWRAM（スタック）を圧迫しません。
- **文字はスプライトです。** GBA のスプライトは最大128個（1スプライトに4〜6文字）なので、同時に大量の文字を出す画面を作るときは注意してください。
- ウィンドウ同士は重ねない前提です（片方を消すともう片方に穴が開きます）。サブメニューは隣に開くか、親を閉じてから開きます。

## 拡張のしかた

| やりたいこと | 編集する場所 |
| --- | --- |
| 技を追加 | `SpellId`（rpg_spells.h）に追加 → `rpg_spells.cpp` に1行 → `rpg_classes.cpp` の習得表に `{ レベル, 技 }` を追加 |
| 技の名前を変更 | `rpg_spells.cpp` の表の文字列を書き換えるだけ（他のコードは名前に依存しません） |
| アイテムを追加 | `ItemId` に追加 → `rpg_items.cpp` に1行 |
| 敵を追加 | 32x32 の BMP+JSON を `graphics/` に置く → `EnemyId` に追加 → `rpg_enemies.cpp` に1行 → マップの `EncounterGroup` に入れる |
| 職業・初期パーティを変更 | `rpg_classes.cpp` / `Party::init_new_game()`（rpg_party.cpp） |
| 町・ダンジョンを追加 | `MapId` に追加 → `rpg_maps.cpp` に ASCII レイアウト・イベント・`maps[]` の項目を書く → 既存マップに `warp` イベントを置いてつなぐ |
| タイルの種類を追加 | `TileId` の **末尾** と `rpg_maps.cpp` の `tiles[]`（記号・通行可否・エンカウント倍率）に追加し、`gen_placeholder_assets.py` の `FIELD_TILES` に同じ順番で絵を足す（下の「マップタイル」参照） |
| 装備品を追加 | `ItemId` に追加 → `rpg_items.cpp` に1行（`kind` = weapon/armor、`classes` = 装備できる職業、`bonus` = 能力の加算値）。店の `stock`・宝箱の `item` にそのまま使える。装備は「アイテムの一種」なので所持数・売買・セーブの仕組みを共有する |
| ダンジョンの階・町を追加 | `MapId` に追加 → `rpg_maps.cpp` に ASCII レイアウト・イベント・出現テーブルを書く。階段は `stairs_up`/`stairs_down` タイル（`u`/`d`）+ `warp` イベント。ワープ元・先が通れないタイルだとビルドエラーになる（`valid_events()`） |
| NPCを歩かせる | その `MapEvent`（`npc_graphics` ありの会話・宿屋など。宝箱は不可）に `.movement = NpcMovement::wander, .wander_radius = 3` を足す。1マップに最大4体（`max_map_walkers`）。位置はセーブされず、マップを読み込むと元の場所に戻る（プレイヤーがその場所にいれば近くの空きマスに出る） |
| 道具屋を置く | マップの `events` に `EventType::shop`（`npc_graphics = 5`、`pages` = あいさつ、`stock` = 売る `ItemId` の配列）を書く |
| 回復の泉を置く | マップに `TileId::spring` のタイル（記号 `F`）を置き、同じ座標に `EventType::spring`（`pages` = 説明文、`price` = 1回の料金、0 なら無料）のイベントを書く。蘇生は宿屋だけ、という差をつけてある |
| 回復アイテムの効果・価格を調整 | `rpg_items.cpp` の表（`power` + `variance`、`price`）。魔法も同じ `Effect` 形式なので `rpg_spells.cpp` で同様に調整できる |
| 価格を変更 | 購入価格は `rpg_items.cpp` の `price`。売値は購入価格の何%かを `sell_percent`（rpg_shop.h）で一括変更 |
| 宝箱を置く | `FlagId`（rpg_flags.h）に名前を追加 → マップの `events` に `EventType::chest`（`npc_graphics = 3`、`flag`、`item` + `item_amount` / `gold`）を書く |
| フラグを追加（ボス撃破・イベント済みなど） | `FlagId` に追加し、`state.flags.get/set()` で読み書きする。セーブに自動で含まれる（最大64個、`max_flags`） |
| イベントの種類を追加（店など） | `EventType` に追加 → 処理を `rpg_events.cpp` に書き（はい/いいえは `ask_yes_no()`）、`FieldScene::_interact()` から呼ぶ。踏んで発動するものは `_on_step()` |
| 敵の AI | `BattleScene::_enemy_turn()` |
| 敵の行動回数の確率 | `action_chances[]`（rpg_enemies.cpp）。敵ごとのランクは `EnemyData::rank` |
| ダメージ計算式 | `roll_physical_damage()` / `roll_effect()`（rpg_party.cpp） |
| 経験値カーブ | `exp_for_level()` / `enemy_exp_for_level()`（rpg_classes.h） |
| セーブ内容を変更 | `SaveData`（rpg_game_state.cpp）。変更したら `save_version` を上げる（古いセーブは無視される）。フラグの `FlagId` は並べ替え・削除しない |

マップは最大 32x32 タイル（512x512 px）です。それより大きいマップが必要になったら、Butano の big map 対応や
マップのストリーミングに `FieldScene` を置き換えてください。

### 技（レベルで覚える）
戦闘の「わざ」コマンドで MP を消費して使います。名前は `rpg_spells.cpp` の表（`RPG_T("英語", "日本語")`）を書き換えるだけで
差し替えられます（新しい漢字を使ったら `python3 tools/gen_japanese_font.py` を再実行）。

| キャラ | 習得Lv: 技（MP）― 効果 |
| --- | --- |
| 主人公 | 5: ためる (2) 次の武器攻撃が2倍 ・ 10: なぎ払い (4) 全体80% ・ 15: みねうち (5) 120%+50%で気絶 ・ 20: 全力斬り (8) 200% ・ 30: 究極斬り (16) 350% |
| シオン | 6: つきさす (3) 130% ・ 12: 連続突き (6) 80%×2 ・ 18: 旋風槍 (9) 全体110% ・ 28: 無限槍 (18) ランダム85%×4 |
| ミレア | 4: ヒール (3) 30〜40 ・ 9: ベホイミ (6) 80〜100 ・ 14: ベホマ (10) 全快 ・ 19: ザオラル (12) 50%で蘇生(HP半分) ・ 27: 完全回復 (30) 全員全快 |
| ノクス | 5: メラ (2) 10〜16 ・ 10: メラミ (6) 55〜70 ・ 15: メラゾーマ (12) 120〜150 ・ 30: 終焉の炎 (28) 全体220〜270 |

- 「%」は通常攻撃ダメージに対する倍率（`EffectType::physical`）。魔法は固定ダメージ（`EffectType::damage`）。
- 気絶した敵は次の自分のターンを失います。ボス・ラスボスには効きません。
- 仲間は主人公のレベルで加入するので、加入時点でそのレベルまでの技を覚えています。
- 敵が使う呪文は従来どおりファイア / ブリザードです（`SpellId::fire` / `blizzard`、敵専用）。
- 1キャラが覚えられる技は `max_known_spells`（rpg_party.h、現在8）までです。増やすときはこの値も上げてください。

### 経験値バランス（最大 Lv100・本編クリア Lv60 前後）
必要経験値は 3 次式（`exp_for_level()`）で、序盤は数戦で上がり、後半ほど 1 レベルが重くなります。

| Lv | 2 | 5 | 10 | 20 | 30 | 40 | 50 | 60 | 100 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 累計EXP | 12 | 312 | 3,132 | 28,272 | 99,412 | 240,552 | 475,692 | 828,832 | 3,901,392 |

敵の経験値は **`enemy_exp_for_level(その敵と出会う想定Lv, 倍率%)`** で決めています（rpg_enemies.cpp）。
倍率 100% は「想定Lvどおりの敵 2〜3 体と 2 + Lv×0.3 戦で 1 レベル」（Lv60 まで約 670 戦）という長編向けの基準です。
本編はランダム戦闘が約 150 戦・ボス 12 戦と短いので、通常敵は 400〜800%、ボスは 1000〜6000% にしてあります。

| 到達点 | 1章ボス | 2章 | 3章 | 4章 | 5章 | 7章 | 8章 | ラスボス戦 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 主人公のLv（試算） | 11 | 15 | 20 | 28 | 36 | 46 | 56 | 約59 |

各ダンジョンで 10〜12 戦する前提の試算です。戦闘を避けがちなら Lv52 前後、多めに戦うと Lv66 前後でラスボスに着きます。
Lv61〜100 はやり込み用です。敵の HP・攻撃力などは本編のまま変えていません。

### 敵の行動回数（標準難易度）
`EnemyData::rank` で決まり、確率は `action_chances[]`（rpg_enemies.cpp）で調整できます。

| ランク | 1回 | 2回 | 3回 | 該当する敵 |
| --- | --- | --- | --- | --- |
| `normal` 通常の敵 | 100% | – | – | ランダムエンカウントの敵 |
| `boss` 強敵 | 70% | 30% | – | 各章のボス、灰の将軍 |
| `last_boss` ラスボス | 60% | 30% | 10% | 焔帝（第1・第2形態） |

複数回行動で理不尽にならないよう、「呪文は1ターンに1回まで」「連続攻撃では、他に生存者がいれば直前と同じ相手を狙わない」
という制限を入れています。

### アセットを差し替える
`graphics/` の BMP を同じサイズ・16色インデックスカラー（色0が透過）で上書きして再ビルドするだけです。

| ファイル | 内容 |
| --- | --- |
| `field_tiles.bmp` / `field_palette.bmp` | マップタイル。幅16pxで、16x16タイルを縦に並べる。前半は `TileId` の順、後半は見た目だけの差分タイル（下の「マップタイル」参照） |
| `ui_tiles.bmp` / `ui_palette.bmp` | ウィンドウ枠（8x8 × 10枚の横並び） |
| `player.bmp` | 16x16 × 8コマ（下・上・左・右 × 歩行2コマ） |
| `npc.bmp` | 16x16 × N コマ。`MapEvent::npc_graphics` がコマ番号（0 村人、1 長老、2 宿屋、3 閉じた宝箱、4 開いた宝箱、5 道具屋、6 シオン、7 教団員、8 灰の将、9 ミレア、10 竜、11 旅人、12 ノクス、13 リコ） |
| `enemy_*.bmp` | 32x32 の敵グラフィック |
| `cursor.bmp` | 8x8 のカーソル |

`python3 tools/gen_placeholder_assets.py` を実行すると全画像を再生成（上書き）します。

キャラクター（`player.bmp` / `npc.bmp`）は専用の16色パレット（`CHAR_PALETTE`）で、共通の体（`BODY`）にキャラごとの色と
髪型・帽子・槍などの上書き（`CAST`）を重ねて作っています。新しい人物は `CAST` に1項目足して `gen_npcs()` の末尾に並べます。

道（`:`）は草に接する辺に草がかぶり、水（`~`）は陸に接する辺に岸が付きます（`FieldScene` が隣のタイルを見て
16通りの差分タイルを選ぶだけで、マップデータは変わりません）。

### マップタイル
マップタイルと宝箱（閉・開）は、`tools/gen_placeholder_assets.py` の中に **ASCII のドット絵**（1文字 = 1ピクセル、`paint()`）として
描いてあります。外部の画像ファイルから切り出したタイルはありません。参考画像をもとに 16x16・共通15色パレット
（`FIELD_PALETTE`、色0は未使用）へ描き起こしたもので、スクリプトを直せば同じ絵柄のまま再生成できます。

追加したタイル（`TileId` の末尾。既存の番号・記号は変えていません）:

| 記号 | `TileId` | 内容 |
| --- | --- | --- |
| `f` `l` `b` `W` | `fence` `lamp` `bench` `well` | 村の飾り（柵・街灯・ベンチ・井戸）。通れない。草地用 |
| `B` | `barrel` | 樽。通れない |
| `o` | `magic_circle` | 魔法陣。通れる。`warp` イベントを重ねて使う |
| `I` `G` | `inn_sign` `shop_sign` | 宿屋・道具屋の吊り看板つきの家の壁。扉の隣の `#` の代わりに置く |

**見た目だけの差分タイル**: マップデータを書き換えなくても、`FieldScene` の `tile_graphics()`（rpg_field_scene.cpp）が
周りのタイルを見て絵を選びます。通行可否などの性質は常に `TileId` のままです。

- 屋根（`^`）: 左端・右端に破風板がつく
- 壁（`#`）: 上に屋根があれば家の壁（屋根の直下は1つおきに窓）。なければ石レンガの城壁
- 洞窟の床（`_`）: 外周（`border`）が `wall` のマップ（砦・聖堂・城など）では石畳になる
- 城壁・洞窟の壁: 手前が床のところに、まばらに松明（城壁には鎖も）がかかる
- 松明の光: 松明の左右の壁と、真下の床が少し明るくなる（`glow()` で元のタイルから自動生成）
- 上り階段（`u`）: 奥が洞窟の壁なら梯子になる
- 水（`~`）: 上が岸なら影と波打ち際がつく
- 看板・泉・墓・祭壇・樽・魔法陣: 周りの地面（草 / 灰 / 洞窟の床 / 石畳）の上に描かれる

差分タイルを増やすときは、`gen_placeholder_assets.py` の `FIELD_EXTRA_TILES` / `GROUND_OBJECTS` と、
rpg_field_scene.cpp の `gfx_*` 定数・`GroundObject` を同じ順番にそろえます。

### 日本語対応
- **言語**: `rpg_text.h` の `Language`（既定は `default_language = Language::japanese`）。タイトル画面の `Language` で切り替え。セーブはされないので、起動のたびに既定値に戻ります。
- **2言語テキスト**: `RPG_T("English", "日本語")` と書くと、2つの文字列リテラルを区切り文字（`\f`）でつないだ1つの `constexpr` 文字列になります（ROM に置かれ、`bn::string_view` の表の型はそのまま）。`Window` / `Menu` / `MessageBox` が表示時に `localized()` で現在の言語の側だけを取り出します。`RPG_T` を使っていない文字列はどちらの言語でもそのまま表示されるので、少しずつ訳していけます。
- **実行時に組み立てる文**（数値やアイテム名を含むもの）は `tr("english", "日本語")` で部品を選びます。日本語は UTF-8 で1文字3バイトなので、`bn::string<N>` の容量に注意（`rpg_events.cpp` は 128 にしてあります）。
- **データの名前**: アイテム・呪文・敵・職業（仲間）の `name` も `RPG_T` で書きます。メニューにそのまま渡す場合は自動で切り替わり、文に埋め込む場合は `localized(name)` を通します（`PartyMember::name()` は切り替え済みの名前を返します）。敵名は戦闘開始時の言語で確定します。
- **固有名**: `rpg_names.h` に `RPG_NAME_HERO_JA` などの日本語版マクロがあります。
- **フォント**: 日本語モードでは `graphics/rpg_japanese_16x16_font.bmp`（16x16 セルの可変幅スプライトフォント。半角 6px / 全角 12px）を使います。ASCII・ひらがな・カタカナ・記号は常に入っていて、漢字は **ソースで使っているものだけ** です。
  **新しい漢字を使ったら**フォントを作り直してください（Pillow が必要）:
  ```sh
  python3 tools/gen_japanese_font.py
  ```
  フォントに無い文字を表示しようとすると Butano のエラー画面で止まります（文字化けはしません）。
- **文字数の目安**: メッセージボックスは1行 全角18文字、1ページ3行まで（3行以下のページは行間 16px、4行のページは 12px に詰めて表示）。
- **スプライト数**: 全角文字は1スプライトに2文字です（英語は4〜6文字）。全角18文字×3行で27スプライト。
- **英語フォントに戻す・差し替える**: `Ui` のコンストラクタ（rpg_ui.cpp）で渡している `bn::sprite_font` を変えます。

### BGM・効果音（仮の音）
Butano の Maxmod バックエンドで再生します（`Makefile` の `AUDIOBACKEND := maxmod` / `AUDIO := audio`。変換ツール mmutil は devkitPro に同梱）。
`audio/` の音はすべて `python3 tools/gen_placeholder_audio.py` が生成した短いチップチューン風の仮素材です。

| ID（rpg_audio.h） | ファイル | 鳴る場面 |
| --- | --- | --- |
| `BgmId::town` | `bgm_town.mod` | ランダム戦闘のないマップ（町・村）。明るめ |
| `BgmId::dungeon` | `bgm_dungeon.mod` | ランダム戦闘のあるマップ（草原・洞窟・城など）。暗め |
| `BgmId::battle` | `bgm_battle.mod` | 通常戦闘 |
| `BgmId::boss` | `bgm_boss.mod` | ボス・ラスボスランクの敵がいる戦闘 |
| `BgmId::event_dark` | `bgm_event_dark.mod` | 重要イベント（村の焼き討ち、相棒の過去、王都陥落など）と、焼け跡の村 |
| `BgmId::event_hope` | `bgm_event_hope.mod` | 重要イベント（灯火の祠、帰郷〜エンディング）と、再建後の村 |
| `BgmId::title` | `bgm_title.mod` | タイトル画面。静かでゆっくり |
| `SeId::confirm` / `cancel` | `se_confirm.wav` / `se_cancel.wav` | メニューの決定（A）/ キャンセル（B） |

| `SeId::chest` | `se_chest.wav` | 宝箱を開けたとき |

- **差し替え**: 同じファイル名で上書きして再ビルドするだけです（BGM は .mod / .xm / .it / .s3m、SE は無圧縮の .wav。BGM の形式を変えるときは古い .mod を消す）。
  ファイル名を変える・曲ごとの音量バランスを直すときは `src/rpg_audio.cpp` の表を編集します。
- **曲や SE を増やす**: `BgmId` / `SeId` に追加 → `audio/` にファイル → `rpg_audio.cpp` の表に1行。
- **マップごとの曲**: 既定は自動（エンカウントの有無で町／ダンジョン）。`MapData::bgm` を指定すると上書きできます（章ごとに曲調を変える場合はここ）。
- **イベントの曲**: `story_bgm()`（rpg_story.cpp）にシーンを追加します。シーンが終わるとマップの曲に戻ります。
- **再生**: `audio::play_bgm(id)`（同じ曲なら鳴らし直さない）/ `audio::play_se(id)`。
- **音量・ミュート**: フィールドメニューの「サウンド」で BGM 音量・SE 音量（0〜4）とミュートを変更できます。
  設定はセーブデータとは別に SRAM へ即保存され、次回起動時も有効です（既存のセーブには影響しません）。
- タイトル画面では `BgmId::title` が流れ、最初のマップに入るとそのマップの曲に切り替わります。

仕組み:

- **イベントの出現条件**: `MapEvent::min_progress` / `max_progress`。範囲外のイベントは存在しません（スプライト・当たり判定・会話すべて）。同じタイルに複数置いた場合は先に書いたものが優先。
- **章ごとの台詞**: `MapEvent::chapter_pages` に章ごとのページ集合を並べると、`chapter_index(story_progress)`（= `story_progress / 10`、0 が第1章）で切り替わります。
- **スクリプトイベント**: `EventType::story`（Aボタン）/ `EventType::trigger`（踏む）+ `StoryId`。台本は `src/rpg_story.cpp` に集約。ボス戦は `StoryResult::battle` で開始（逃走不可）、戦闘後の処理は `run_story_after_battle()`。
- **戦闘中の加入・ターン制限**: `StoryResult::battle_join_turn` のターン以降、毎ターンの開始時に `story_battle_reinforce()` が呼ばれ、加入させるかどうかを決めます（E506、E1003）。`battle_turn_limit` を超えると戦闘が打ち切られ、負け扱いになります（E604）。
- **連戦**: 戦闘後の処理で `StoryResult::next` に次の戦闘シーンを入れると、フィールドに戻らず回復なしで続きます（E603）。
- **フラグで消えるイベント**: `MapEvent::gone_flag` を指定すると、そのフラグが立った時点でイベント（ボスのNPCなど）が消えます。順不同で倒せるボス用です（E803・E804）。
- **負けイベント**: `story_defeat_continues()` が true を返すシーンのボス戦は、負けてもペナルティなしで進行します。勝敗どちらの後処理も `run_story_after_battle()`。
- **マップの状態差分**: `rpg_maps.cpp` の `map_states[]`。ハルト村は平和（0〜2）／焼け跡（3〜93）／再建（94〜）、王都グランセルは平和／炎上（52〜）。どの状態も同じサイズで、イベント一覧を共有します。
- **パーティ**: `Party::size` 人だけが在籍（開始時は主人公1人）。`Party::join()` で加入、`Party::leave()` で離脱（レベルと装備を保ったまま `away` で待機し、同じ職で `join()` すると元の状態で戻る）。
- **固有名**: `include/rpg_names.h` のマクロ1か所（アレン / シオン / ハルト / ベルク / ドレイク…）。差し替えはここだけ。
- **全滅時の復帰地点**: `respawn_points[]`（第1章 = ハルト村、第2章 = ベルクの宿前、第3章 = ルナリスの宿前、第4章 = アッシュベルの宿前、第5〜6章 = ドルンの宿前、第7章 = 難民の里の宿前、第8章以降 = 港町の宿前）。
- **キーアイテム**: `ItemKind::key`（使用・装備・売却不可）。
